# planet-gen

Публичный репозиторий: [Planetary-Annihilation-Fandom/planet-gen](https://github.com/Planetary-Annihilation-Fandom/planet-gen). История проекта сохранена из `pa-research-tools/pa/planet-gen`.

Воссоздание генератора планет Planetary Annihilation: по параметрам планеты из системы строит ту же сетку поверхности, уровень воды и лавы, что и сервер игры, раскладывает подбиомы, ставит кисти CSG из системы и расставляет металлические точки по алгоритму игры. Текстуры подбиомов и кистей читаются из файлов `.papa` игры.

- `crates/planet-gen`: библиотека и CLI.
- `app`: просмотрщик на Tauri, React, Carbon и three.js.

Что реализовано и что осталось, кратко описано в [PLAN.md](PLAN.md).

Разработка ведётся через рабочие ветки от `dev`, без pull request; `main` хранит опубликованное состояние. Правила слияний, общей версии CLI и приложения и выпуска с тегом описаны в [docs/publishing.md](docs/publishing.md). История изменений хранится в коммитах.

## Установка

Нужны Rust stable с Cargo, Node.js 20.19+ или 22.12+ и npm. Для окна нужны системные зависимости Tauri 2; на Windows это Microsoft C++ Build Tools и WebView2 Runtime.

```bash
git clone https://github.com/Planetary-Annihilation-Fandom/planet-gen.git
cd planet-gen
```

Ресурсы Planetary Annihilation: TITANS читаются из установленной игры и в репозиторий не входят. Укажите папку `media` через переменную окружения `PA_MEDIA_DIR`; её используют CLI и просмотрщик. Пример для PowerShell:

```powershell
$env:PA_MEDIA_DIR = 'D:\SteamLibrary\steamapps\common\Planetary Annihilation Titans\media'
```

Без переменной сохраняется исходный локальный путь установки: `C:\workroot\software\steam\steamapps\common\Planetary Annihilation Titans\media`. В CLI параметр `--media` имеет приоритет над переменной окружения.

## CLI

```bash
cargo run --release -p planet-gen -- <система.pas|планета.json> --planet 2
```

На вход подходит файл системы с массивом `planets`, отдельная планета системы или её объект `planet`. Параметры:

- `--planet N`: номер планеты в системе;
- `--media DIR`: папка `media` игры, откуда читаются архетипы биомов; по умолчанию `PA_MEDIA_DIR` или исходный локальный путь установки. Для путей `/pa/…` сначала проверяется `pa_ex1` (Titans), затем `pa`; библиотечный `Media::mount` позволяет подключать дополнительные папки поверх ресурсов игры;
- `--slope DEG`: максимальный уклон для металлических точек, по умолчанию 40;
- `--format summary|json|obj`, `--out FILE`: формат и файл результата.

## Просмотрщик

```bash
cd app
npm ci
npm run tauri -- dev
```

Vite работает на фиксированном порту 18500 (`app/vite.config.js` и `app/src-tauri/tauri.conf.json`). В исследовательском окружении PA этот порт также закреплён в общем реестре портов; перед запуском проверьте, свободен ли он. По умолчанию открывается редактор шаблонов. Переключатели системы и случайной планеты временно скрыты; эти режимы доступны через аргументы запуска:

- «Существующая»: планета из систем игры или из открытого файла `.pas` вместе с её кистями CSG;
- «Случайная»: случайное зерно и параметры выбранного архетипа в пределах редактора систем.
- «Шаблоны»: сухая основа планеты, результат JSON-шаблона и канвас его нод.

При запуске собранного окна режим задаётся аргументами: `planet-gen-app <система.pas> --planet N` или `planet-gen-app --random earth`.

Просмотр планеты занимает всё окно; боковые панели накладываются поверх него. Левую панель можно скрыть крестиком и вернуть кнопкой в левом верхнем углу. При выборе ноды её параметры появляются вертикальной панелью поверх канваса графа; закрытие панели снимает выделение.

### Редактор шаблонов

Запустите `planet-gen-app` без аргументов или с `--templates`. Шаблон описывает сторону одного игрока в 1v1 и зеркально применяется ко второму. В канвасе ровно один спавн: создать ещё один спавн, скопировать или удалить существующий нельзя. Поверхность основы остаётся исходным рельефом; зеркальны области и точки металла, но не высоты планеты.

#### Работа с графом

Выберите пример «1v1: спавн, металл, фронт» или «1v1: две ветви». Первый создаёт два спавна и две области металла, по одной на сторону; второй показывает ветвление, схождение, полосу блокера и ориентированную рампу. Создайте пустой шаблон со спавном или копию выбранного.

ПКМ по фону открывает создание металла, блокера, рампы и фронта. ПКМ по ноде позволяет создать дочернюю ноду, скопировать или удалить выбранную. У спавна нет входа, у фронта нет выхода; циклы запрещены. Перетащите выход на вход для соединения, удалите связь через ПКМ. Каждый порт принимает несколько связей. Для отмены доступны Ctrl+Z, для повтора Ctrl+Shift+Z.

Основные параметры видны внутри карточки, название меняется в разделе «Дополнительно». Координаты карточек служат для чтения графа и не влияют на размещение областей. Автоматической раскладки нет; новые связи и параметры не перемещают карточки или камеру. Колесо масштабирует канвас, перетаскивание фона перемещает его; «Вписать граф» показывает все ноды. Ширина панели меняется перетаскиванием левой границы или стрелками клавиатуры, двойной щелчок возвращает стандартную ширину. «Свернуть» освобождает место для планеты. Ширина и камера каждого шаблона сохраняются между запусками.

Параметры нод и seed обновляют области сразу. Радиус и другие параметры основы применяются кнопкой «Сгенерировать основу». Перетаскивание планеты вращает её вместе с областями, колесо меняет расстояние камеры. Зелёные области обозначают спавны, золотые обозначают металл, красные обозначают блокеры, синие обозначают рампы. Белая направляющая идёт от спавна к сопернику, фиолетовая граница отделяет половины. Слои, значки и подписи переключаются слева; выбор области подсвечивает её ноду.

#### Размеры и размещение

Размер задаёт диаметр области в процентах длины пути от спавна до фронта, равной четверти большой окружности: `диаметр = size / 100 × πR / 2`. Для размера 10 на планете радиуса 400 получится около 63 единиц по поверхности, на радиусе 800 около 126. Добавление нод не уменьшает заданные размеры.

У спавна есть размер; у металла размер и насыщенность; у блокера размер и форма (окружность или полоса); у рампы размер и угол относительно направляющей. У фронта нет геометрических параметров. Насыщенность задаёт число металлических точек в эталонной области размера 10%; фактическое количество пропорционально площади сферического диска, округляется до целого и умножается на общий множитель металла. Парные точки зеркальны. Полоса имеет ширину в четверть длины, рампа отображается вытянутой областью с указателем направления. Это резервируемые области для будущих CSG, рельеф они не меняют.

Генератор сначала пробует направляющую, затем перебирает смещения по полусфере с возвратом к предыдущим решениям. Каждый дочерний центр находится дальше от своего спавна, чем центры входов. Области не пересекаются и целиком остаются в своей половине. Ветвления и схождения не размножают ноду: каждая создаёт одну область на сторону. Каждый подключённый фронт обозначает ту же границу сторон.

Тесный граф перераспределяется по сторонам от направляющей. Например, цепочка из 12 областей размера 30% не помещается на одной дуге, но размещается по полусфере без изменения размеров. Для полос и рамп резервируется описанная окружность. Поиск ограничен сеткой из 33 расстояний и 48 направлений и бюджетом 180000 проверок; отказ означает отсутствие найденного размещения, а не математическое доказательство невозможности. Редактор объясняет причину и предлагает уменьшить размеры или число областей. Ошибка убирает результат целиком и блокирует его экспорт. Отсоединённые ноды остаются в графе с предупреждением; незавершённые пути также отмечаются.

#### Сохранение и формат JSON

Шаблоны 1v1 сохраняются отдельно от старых FFA-данных. JSON версий 1 и 2 не преобразуется автоматически: старое хранилище остаётся нетронутым, интерфейс показывает предупреждение и кнопку скачивания исходного JSON. Импорт старого файла сохраняет его в отдельный архив. Повреждённые данные нового хранилища доступны для скачивания и копируются в архив восстановления до перезаписи.

JSON версии 3 содержит `id` на латинице, `name`, `players: {min: 2, max: 2, default: 2}`, массивы `nodes` и `links`. Нода содержит уникальный `id`, `name`, `kind` (`spawn`, `metal`, `blocker`, `ramp`, `front`), `canvas: {x, y}` и параметры своего типа из `app/src/node-types.js`. `size` принимает целые 1–100, `density` целые 1–100, `shape` принимает `circle` или `strip`, `orientation` целые от −180 до 180 градусов. Связь содержит `from` и `to`. Допустимо до 60 нод, 200 связей и 10000 металлических точек. Примеры версии 3 находятся в `app/src/templates/duel.json` и `branches.json`; старые примеры оставлены для архива.

Кнопка «JSON» скачивает выбранный шаблон, импорт требует уникальный id. «Сохранить результат» выгружает `base` (параметры, очистку, поверхность) и `applied` (шаблон, параметры, зоны, связи, направляющую, границу и координаты объектов). Блокеры и рампы выгружаются как `regions` с формой и ориентацией; список применённых CSG пуст. Это формат редактора, а не система `.pas` для игры. История отмены действует до перезапуска.

Сборка интерфейса: `cd app` затем `npm run build`. Интерфейс использует React и компоненты Carbon с тёмной темой Gray 90 (`g90`). Автономное окно: `npm run tauri -- build --debug --no-bundle`; результат: `target/debug/planet-gen-app.exe`, без зависимости от Vite при запуске.

Поверхность окрашивается базовыми текстурами подбиомов с весами по вершинам и триплоскостной проекцией. Игра рисует рельеф через виртуальную текстуру, поэтому мелкий рисунок отличается.

## Структура интерфейса

`app/src/App.jsx` связывает режимы работы, команды Tauri и 3D-сцену. Формы, параметры внутри нод, результат и граф находятся в `app/src/components/`; модель шаблонов с историей и сохранением находится в `app/src/model/template-store.js`. Граф построен на React Flow с пользовательскими карточками и компонентами Carbon. Three.js подключается к React через ref и освобождает ресурсы при размонтировании.

Тема задаётся через Carbon `Theme` с `theme="g90"`, размеры и типографика используют токены Carbon. Шрифты IBM Plex включаются в сборку и доступны без сети. Локальные порты: 18500 для Vite, 18501 для необязательного CDP WebView2 при отладке; перед запуском проверяйте их владельцев.

## Расхождения с игрой

- Навигационную сетку и коллизии структур игры заменяет проверка уклона треугольника, поэтому отдельные металлические точки на крутых склонах могут не совпадать.
- При заданном `metalSpotLimit` игра перемешивает точки через `std::random_device`; такой результат не повторяется и в самой игре.
- Расстояние до воды для подбиомов считается алгоритмом Дейкстры по вершинам сетки, а не чамфер-расстоянием игры; границы подбиомов могут немного сдвигаться.
- Кисти CSG из `planetCSG` устанавливаются проекциями игры и применяются булевыми операциями с BSP-разбиением. Металлические точки ищутся на итоговой поверхности вместе с гранями кистей. Точное совпадение геометрии с BSP-алгоритмом игры пока не подтверждено.
- Процедурные кисти и декали биомов (`genBrushes`, `genDecals`) и стартовые зоны не учитываются.
