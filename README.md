# planet-gen

Публичный репозиторий: [Planetary-Annihilation-Fandom/planet-gen](https://github.com/Planetary-Annihilation-Fandom/planet-gen). История проекта сохранена из `pa-research-tools/pa/planet-gen`.

Воссоздание генератора планет Planetary Annihilation: по параметрам планеты из системы строит ту же сетку поверхности, уровень воды и лавы, что и сервер игры, раскладывает подбиомы, ставит кисти CSG из системы и расставляет металлические точки по алгоритму игры. Текстуры подбиомов и кистей читаются из файлов `.papa` игры.

- `crates/planet-gen`: библиотека и CLI.
- `app`: просмотрщик на Tauri и three.js.

Что реализовано и что осталось, кратко описано в [PLAN.md](PLAN.md).

## Установка

Нужны Rust stable с Cargo, Node.js 20.19+ или 22.12+ и npm. Для окна нужны системные зависимости Tauri 2; на Windows это Microsoft C++ Build Tools и WebView2 Runtime.

```bash
git clone https://github.com/Planetary-Annihilation-Fandom/planet-gen.git
cd planet-gen
```

Ресурсы Planetary Annihilation: TITANS читаются из установленной игры и в репозиторий не входят. Укажите папку `media` через переменную окружения `PA_MEDIA_DIR`; её используют CLI и просмотрщик. Пример для PowerShell:

```powershell
$env:PA_MEDIA_DIR = 'D:\SteamLibrary\steamapps\common\Planetary Annihilation Titans\media'
```

Без переменной сохраняется исходный локальный путь установки: `C:\workroot\software\steam\steamapps\common\Planetary Annihilation Titans\media`. В CLI параметр `--media` имеет приоритет над переменной окружения.

## CLI

```bash
cargo run --release -p planet-gen -- <система.pas|планета.json> --planet 2
```

На вход подходит файл системы с массивом `planets`, отдельная планета системы или её объект `planet`. Параметры:

- `--planet N`: номер планеты в системе;
- `--media DIR`: папка `media` игры, откуда читаются архетипы биомов; по умолчанию `PA_MEDIA_DIR` или исходный локальный путь установки. Для путей `/pa/…` сначала проверяется `pa_ex1` (Titans), затем `pa`; библиотечный `Media::mount` позволяет подключать дополнительные папки поверх ресурсов игры;
- `--slope DEG`: максимальный уклон для металлических точек, по умолчанию 40;
- `--format summary|json|obj`, `--out FILE`: формат и файл результата.

## Просмотрщик

```bash
cd app
npm ci
npm run tauri -- dev
```

Vite работает на фиксированном порту 18500 (`app/vite.config.js` и `app/src-tauri/tauri.conf.json`). В исследовательском окружении PA этот порт также закреплён в общем реестре портов; перед запуском проверьте, свободен ли он. У окна три режима:

- «Существующая»: планета из систем игры или из открытого файла `.pas` вместе с её кистями CSG;
- «Случайная»: случайное зерно и параметры выбранного архетипа в пределах редактора систем.
- «Шаблоны»: сухая основа планеты, результат JSON-шаблона и канвас его нод.

При запуске собранного окна режим задаётся аргументами: `planet-gen-app <система.pas> --planet N` или `planet-gen-app --random earth`.

### Редактор шаблонов

Откройте «Шаблоны» или запустите `planet-gen-app --templates`. Два примера «Соседние фронты» и «Общие области борьбы» поддерживают FFA на 3–12 участников. Число игроков, seed шаблона и множитель металла меняют результат автоматически; кнопка «Сгенерировать основу» отдельно перестраивает рельеф по параметрам генератора. В основе отключены вода, лава, CSG и исходный металл.

Зелёные залитые области обозначают спавны, золотые области с точками обозначают металл, красные обозначают блокеры, синие обозначают рампы. Над областями показаны графические значки флага, кристалла, стены и наклонной плоскости. Их можно отключить отдельно. CSG показаны условными куполами и пока не меняют геометрию или проходимость. Широкие полосы показывают связи между экземплярами нод. Выбор области или ноды подсвечивает соответствующие элементы; слои и подписи отключаются слева. Баланс и пригодность мест для строительства не проверяются.

Создайте пустой шаблон со стартовой нодой или копию существующего. ПКМ по фону открывает создание спавнов, промежуточных областей, металла, блокеров и рамп. ПКМ по ноде открывает создание дочерней ноды, её копирование и удаление. Дочерняя нода автоматически подключается к выходу выбранной. Выбранная нода настраивается внизу панели; форма строится по схеме её типа. Углы в интерфейсе задаются в градусах. Для металла доступны точки, для блокеров доступны цепочки и высота, для спавнов доступны распределение и количество.

Перетаскивание ноды меняет её положение на канвасе, а не на планете. Соедините выход с входом, чтобы передать результат генерации; каждый порт принимает несколько связей. ПКМ по соединению удаляет его, циклы и входы стартовых нод запрещены. Отмена и повтор доступны в меню ПКМ и через Ctrl+Z, Ctrl+Shift+Z. Выбранную ноду можно скопировать или удалить; последнюю стартовую ноду удалить нельзя. «Разложить граф» в контекстном меню сбрасывает ручные положения и располагает граф по зависимостям.

Положение дочерних областей вычисляется из входных экземпляров. Доступны режимы: область от каждого входа, середины дуг между входами, общий центр входов и два противоположных направления от кольца входов. Для нескольких входных нод середины рассчитываются по игроку или близости. У симметричного кольца общий центр неопределён; редактор сообщает об этом, сохраняя возможность редактировать граф. Удаление, направление и разброс смещают результат относительно входов. Фиксированных якорей металла и CSG нет. Отсоединённые ноды остаются на канвасе без результата. Фиолетовые области обозначают промежуточные результаты, которые можно передавать другим нодам.

Панель нод расширяется за левую границу; двойной щелчок по границе возвращает стандартную ширину. Разделитель также управляется клавишами влево и вправо. Ширина сохраняется между запусками. Колесо меняет масштаб графа, перетаскивание фона перемещает его, «Вписать граф» в меню ПКМ показывает всю структуру.

JSON-примеры находятся в `app/src/templates/`. Параметры, связи и положения нод сохраняются между запусками, история отмены действует до перезапуска. JSON можно скачать и импортировать с уникальным id. «Сохранить результат JSON» выгружает `base` (параметры, очистка, поверхность) и `applied` (шаблон, параметры, зоны, фактические связи и координаты спавнов, металла и условных CSG). Это формат редактора, не готовая система `.pas` для игры.

Обязательные поля шаблона: `version: 2`, `id` на латинице, `name`, диапазон `players` с `min`, `max`, `default`, массивы `nodes` и `links`. У ноды есть уникальный `id`, `name`, `kind` (`spawn`, `region`, `metal`, `blocker`, `ramp`) и угловой `radius` в радианах. Схемы параметров и начальные значения находятся в `app/src/node-types.js`. Для дочерних нод `placement` содержит `mode`, `distance`, `bearing`, `jitter`, `pairing`, `side`. Все углы внутри JSON хранятся в радианах. Поле `canvas: {x, y}` хранит положение в редакторе. JSON версии 1 автоматически переводится в новую модель при загрузке.

Для металла `spots` задаёт число точек. Блокеры с `pattern: gate` используют `chain: {count, step, gap}`: по `count` перекрывающихся куполов с каждой стороны прохода, `step` задаёт угловой шаг, `gap` задаёт удаление ближайшего центра от середины прохода. Связь содержит только `from` и `to`; фактические соединения областей рассчитываются по данным генерации. Защита от чрезмерного разрастания ограничивает результат 600 областями, 10000 металлическими точками и 4000 соединениями областей.

Проверки: `cd app` затем `npm test` (воспроизводимость, масштабирование, очистка, сферические примитивы), `npm run build`. Автономное окно: `npm run tauri -- build --debug --no-bundle`; результат: `target/debug/planet-gen-app.exe`, без зависимости от Vite при запуске.

Поверхность окрашивается базовыми текстурами подбиомов с весами по вершинам и триплоскостной проекцией. Игра рисует рельеф через виртуальную текстуру, поэтому мелкий рисунок отличается.

## Расхождения с игрой

- Навигационную сетку и коллизии структур игры заменяет проверка уклона треугольника, поэтому отдельные металлические точки на крутых склонах могут не совпадать.
- При заданном `metalSpotLimit` игра перемешивает точки через `std::random_device`; такой результат не повторяется и в самой игре.
- Расстояние до воды для подбиомов считается алгоритмом Дейкстры по вершинам сетки, а не чамфер-расстоянием игры; границы подбиомов могут немного сдвигаться.
- Кисти CSG из `planetCSG` устанавливаются проекциями игры и применяются булевыми операциями с BSP-разбиением. Металлические точки ищутся на итоговой поверхности вместе с гранями кистей. Точное совпадение геометрии с BSP-алгоритмом игры пока не подтверждено.
- Процедурные кисти и декали биомов (`genBrushes`, `genDecals`) и стартовые зоны не учитываются.
