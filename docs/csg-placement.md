# Установка кистей CSG

Справочник описывает поля `planetCSG`, используемые генератором и просмотрщиком, и проекции геометрии. Формулы сверены статически через Ghidra MCP по серверу сборки 14190493. Булево разбиение в `csg.rs` и `bsp.rs` — собственная реализация; совпадение всех граничных случаев с нативным BSP не гарантируется.

## Поля экземпляра

| Поле | Значение |
| --- | --- |
| `spec` | Спецификация кисти; поле `papa` указывает исходный меш |
| `transform` | Матрица по строкам, 12 или 16 чисел; для позиции используются первые три строки: `world = R × local + t`, `t = [m3, m7, m11]` |
| `proj` | Способ деформации уже преобразованных вершин; отсутствующее или неизвестное значение означает `BP_Terrain` |
| `op` | Поддерживаются `BO_Add` и `BO_Subtract`; операции учитываются по порядку массива |
| `position`, `height`, `scale`, `rotation` | Параметры редактора; при чтении готового экземпляра геометрия определяется `transform`, повторно применять эти поля нельзя |
| `mirrored` | В движке меняет порядок обхода граней, а не координаты вершин; в нашей реализации внешняя ориентация замкнутого объёма восстанавливается по матрице и знаку объёма |

Высота установки — длина вектора переноса матрицы. Проекции используют разницу высоты исходной поверхности под вершиной и под центром кисти; отдельного автоматического переноса центра на рельеф нет. Кисти выбирают высоты исходной поверхности, поэтому предшествующая кисть не становится основанием для следующей. Для полностью совпадающих `spec`, `transform` и `proj` генератор сохраняет только последний экземпляр: его операция определяет итоговое содержимое этого объёма, а повторные грани приводили бы к мерцанию.

## Геометрия PAPA

Кисть загружает меши, на которые ссылаются модели PAPA, в порядке моделей и их `meshBindings`. Таблица мешей сама по себе не определяет видимую геометрию: неиспользуемые меши пропускаются, повторные привязки создают отдельные экземпляры. К каждой вершине сначала применяется матрица `meshToModel` привязки, затем `transform` кисти и выбранная проекция. Матрица `modelToScene` относится к раскладке исходной сцены и в этом пути движка не применяется.

Матрицы PAPA хранятся по столбцам. Проверка локального Z для `BP_Terrain_BelowZero` выполняется после `meshToModel`, до `transform` кисти. Пропуск `meshToModel` приводил к неверному положению лавовых кистей: например, у `lava_plateau_09` привязка содержит смещение примерно `[90.29, 160.20, 0]`, а у `lava_plateau_06` — `[0, 0, -7.59]`. На Angel's Causeway это создавало крупные летающие фрагменты, которых нет в игре.

## Проекции

Обозначения: `w` — вершина после матрицы, `u = normalize(t)`, `d = normalize(w)`, `a = dot(w, u)`, `H(d)` — радиус исходной поверхности. Нативный `sampleHeight` возвращает высоту относительно радиуса планеты; в разности двух значений радиус сокращается.

| Проекция | Преобразование |
| --- | --- |
| `BP_None` | Только матрица, результат `w` |
| `BP_Arch` | `d × a`, без поправки рельефа |
| `BP_Terrain` | `d × (a + H(d) − H(u))` |
| `BP_Terrain_BelowZero` | Формула Terrain только для исходного локального `z ≤ 0`; вершины с `z > 0` сохраняют `w`, независимо от поворота и масштаба |
| `BP_Bend` | Тангенциальное смещение переводится в дугу с углом `length(w − u × a) / length(t)`; затем вдоль нового луча добавляется `H(d) − H(u)`, выбранное по исходному направлению вершины |
| `BP_Longitude` | Северное смещение меняет широту, восточное — долготу с делителем `length(t) × cos(новая широта)` |
| `BP_LongitudePinch` | Как Longitude, но делитель долготы равен `length(t)` |

В Bend и долготных проекциях при угле между `u` и `d` не больше `0.0001` используется формула Terrain. В остальных точках исходный радиус проекции равен `abs(a)`. Долготные проекции выбирают поправку рельефа уже по новому направлению и добавляют её только к мировым X/Y: Z остаётся результатом изгиба. Это особенность проверенной функции движка. На точном полюсе долготные проекции вырождены, поскольку ось вращения нулевая.

## Пересечения и отображение

Булевы операции сохраняют только грани итогового тела. Внутренние части добавляющей кисти скрываются поверхностью и другими кистями; при вычитании остаются обращённые в вырез стенки и дно. Просмотрщик рисует оба вида граней сплошными в слое «CSG». Красный каркас вычитания включается отдельно.

Исходный терраин формируется настройками планеты; CSG создаёт геометрию пересечения с ним. Матрица не пересчитывается из служебных параметров редактора. Экспорт CLI и просмотрщик используют общий крейт `planet-gen`.

## Источник правил

| Функция в сервере 14190493 | RVA | Подтверждает |
| --- | --- | --- |
| `Brush::parse` | `0x2f9730` | Чтение полей экземпляра и вызов обновления геометрии |
| `Brush::updateTransform` | `0x2f2670` | Геометрия строится по сохранённой матрице |
| `zu::parseMat4x4f` | `0x491120` | Форматы матрицы и порядок элементов |
| `parseBrushProjection` | `0x2c0b90` | Список проекций и значение Terrain по умолчанию |
| `Csg::updateGeometry` | `0x2f1040` | Матрица, проекции, проверка исходного Z, разворот граней |
| `BrushSpec::parse` | `0x2c0f90` | Проход по моделям PAPA и преобразование их в геометрию кисти |
| `papa2Manifold` | `0x2be730` | Использование привязок мешей и `meshToModel` до установки кисти |
| `PlanetSurface::sampleHeight` | `0x2d5ce0` | Выбор высоты лучом по исходной геометрии |
| `Csg::csgFilter` | `0x2f8040` | Упорядоченная фильтрация пересекающихся кистей |

Декомпилированные тела функций в репозитории не хранятся.

## Проверка реализации

Проверены сборки CLI и Tauri, загрузка A-SAT с 73 кистями и выбор системы/планеты. В Tauri и редакторе игры открыта одинаковая проверочная система с лунным `crater_01`, лавовым `lava_volcano_01`, их пересечением, подъёмом лавовой кисти на 20 единиц и изменением масштаба с 0.6 до 1.0. Сверка с игрой визуальная: она подтверждает расположение, контур и изменение посадки, но не равенство всех вершин нативной геометрии.

Разовыми проверками вне Git подтверждены формулы проекций, граница локального Z для BelowZero, приоритет матрицы над параметрами редактора, эквивалентность матриц 3×4 и 4×4, влияние порядка операций и отсутствие повторных граней у одинаковых экземпляров. CLI и команда Tauri выдали одинаковые треугольники и данные CSG для планеты с пересекающимися кистями. Материалы и текстурирование CSG остаются отдельной задачей.

На Angel's Causeway проверено исправление загрузки `meshToModel`: при том же ракурсе исчезли ошибочные летающие фрагменты, все 72 кисти загружаются без пропусков. Проверены также привязки мешей, смещения по X/Y/Z и исключение неиспользуемой геометрии из PAPA.
